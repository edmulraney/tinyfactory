# Design

> Draft generated by the factory bootstrap. Revise it when the product earns a look of its own.

How {{name}} looks and behaves. `ARCHITECTURE.md` says how the code is organised; this says how the interface is. Most of it is checked by a linter before anyone reviews; the rest is judgement.

## The system

- **Components come from shadcn/ui**, in `src/components/ui`. Compose them; do not restyle or rewrite them. When a screen needs one that is not there (a dialog, a select), add it with `pnpm dlx shadcn@latest add <name>` from `apps/web`. Never hand-write a button, input or dialog.
- **Product components** are built from those and live in `src/components`. A pattern becomes a component at its second use.
- **Colour is a closed set of named tokens**, defined in `src/app/globals.css`. Tailwind's default palette has been removed, so `bg-blue-500` does not exist.

  | Token | Use |
  |---|---|
  | `background`, `foreground` | The page and its text. The page is the palette's lightest grey, not white, so cards read as raised |
  | `muted`, `muted-foreground` | Quiet surfaces and secondary text |
  | `primary`, `primary-foreground` | The one main action on a screen |
  | `secondary`, `accent` | Lesser actions, hover and selected states |
  | `card`, `popover` | Raised surfaces. White |
  | `border`, `input`, `ring` | Lines, field outlines, focus |
  | `destructive` | Errors and irreversible actions. The only colour that is not grey. As shadcn ships it, the destructive button and badge fail the contrast check (3.8:1 where 4.5:1 is needed), so the token needs darkening before its first use |

- **Sizes come from Tailwind's scale.** No one-off values: `w-[437px]` and `text-[#333]` are refused.
- **Light theme only for now.** The dark tokens are in the theme but nothing switches them on.

Adding a colour, changing a token or turning on dark mode is a design decision: it means editing `globals.css`, and a pull request that changes the theme waits for the owner.

## Principles

These need judgement. The architecture reviewer checks them on every interface change.

- **Quiet interface, loud content.** Grey scale. Colour marks an error or a destructive action and nothing else.
- **One primary action per screen.** Everything else is secondary or a link.
- **Space before boxes.** Separate things with whitespace, then a border. Fills and shadows are the last resort.
- **Type makes the hierarchy.** Size and weight, never colour or decoration.
- **Every view has its empty, loading and error states.** A screen that only works with data is not finished.
- **Works at 375px wide and by keyboard.**
- **Copy is plain.** Sentence case, no exclamation marks, and buttons say what they do.

## What checks what

| Rule | Checked by |
|---|---|
| A colour outside the tokens | Lint: `better-tailwindcss/no-unknown-classes` |
| A one-off value | Lint: `better-tailwindcss/no-restricted-classes` |
| Two classes that fight (`p-2 p-4`) | Lint: `better-tailwindcss/no-conflicting-classes` |
| Unreadable contrast, a control with no name, an image with no text | The accessibility scan every end-to-end test runs (`e2e/test.ts`) |
| The principles above | The architecture reviewer |
