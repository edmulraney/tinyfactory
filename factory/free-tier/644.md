### #644. Visitors are counted by Vercel's Web Analytics

- **Set:** `vercel.sh` switches on the Vercel project's Web Analytics, and `scaffold.sh` renders Vercel's `Analytics` component in a new app's layout, so each page view is sent to Vercel (ticket #644; `decisions.md` [S644a](../decisions/644.md)).
- **Protects:** Neon's 100 compute-hours a month, which a page view written to the project's own `usage_events` table would spend.
- **Why:** a founder needs to know how many people visit before they sign up, and where they came from. Vercel counts page views, visitors and referrers with nothing for the factory to store or to run.
- **Numbers:** read from Vercel's page "Pricing for Web Analytics" on 2026-11-22. The Hobby plan includes 50,000 events a month, shared by every project of the account, for any number of projects. An event is a page view or a custom event, and Hobby records no custom events, so an event a feature records stays in `usage_events`. Hobby reports the last month. Over 50,000, collection pauses after three days of grace, and nothing is charged.
- **Automated:** yes. Vercel documents only the dashboard's Enable button; `vercel.sh` calls the endpoint its OpenAPI description lists ([S644b](../decisions/644.md)).
