### #165. Vercel builds nothing for a change to the factory's own folders

- **Set:** `pnpm-workspace.yaml` lists `factory`, `.claude` and `.github` beside `apps/*`, and each holds a `package.json` with a name and nothing else (ticket #165; `decisions.md` [M165a](../decisions/165.md) to [M165c](../decisions/165.md)). `scaffold.sh` writes the same list for a new project, and the three files are in the bootstrap's manifest.
- **Protects:** Vercel's 100 deployments a day, and Neon's 9 preview slots ([entry 8](entry-8.md)).
- **Why:** Vercel skips a project that a commit does not affect, and since 21 October 2026 a skipped deployment does not count toward the limit. But it treats a change to any file outside the workspace's packages as a change to everything, and the workspace held only `apps/*`, so a commit under `factory/` was built in full. The Ignored Build Step would not help: a build it cancels still counts.
- **Numbers, before:** every push to a pull request and every merge was one deployment, whatever it changed. 16 November used all 100 of the day's deployments. Of the 37 pull requests GitHub lists as merged that day, 24 changed nothing outside the three folders, 8 changed a file at the root or under `product/` as well, and 5 changed the app or the root's package files.
- **Numbers, after:** worked out, not measured. A pull request that changes only the three folders uses no deployment, where it used 2 and 1 more for each fix round: on a day like 16 November, 24 of 37 pull requests. It holds no Neon preview slot either, having no preview. The commit that installs an approved workflow change on `main` changes only `.github/`, so it is one deployment fewer as well.
- **What it does not save:** a change to a file at the repo's root (`CLAUDE.md`, `README.md`) or under `product/` is still built, for the app or not (`decisions.md` [M165b](../decisions/165.md)): 8 of the 37.
- **After a merge:** a ticket whose merge Vercel skipped is not marked `deployed`, because nothing was; `ship.sh` says so on the pull request and its job passes (`decisions.md` [M165c](../decisions/165.md)). One more call to GitHub in a job that already runs, so no Actions minutes.
- **Automated:** yes. It relies on the project's "Skip deployment" setting, which Vercel switches on for a new project; this project's is on, as its skipped empty commits show.
