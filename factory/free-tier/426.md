### #426. Agent jobs run on a runner the owner names

- **Set:** the four jobs that run an agent (`implement`, `fix`, `retro`, `review`) take `runs-on` from the repository variable `AGENT_RUNNER`, and GitHub's hosted runner when it is unset (ticket #426; `decisions.md` [A1](../decisions/setup.md), [A426a](../decisions/426.md), [A426b](../decisions/426.md)). Every other job stays on GitHub's hosted runner. `manual-steps.md` has the owner's steps.
- **Protects:** Actions minutes.
- **Numbers:** those jobs, `review` then being two, `adam` and `ryan`, were billed 6,108 of the 9,064 minutes of 14 to 18 November 2026 ([entry #388](388.md)). GitHub's price, read on 20 November 2026 from its pages "GitHub Actions billing" and "Actions runner pricing": a self-hosted runner's usage "remains free independently and does not reduce the included compute usage", in a private repository as in a public one, and a hosted Linux 2-core runner is $0.006 a minute. The Free plan's allowance is written there as $12 of compute a month, which is 2,000 such minutes. So with the variable set those jobs are billed nothing, where the five days' 6,108 minutes are $36.65 at the hosted price.
- **What it costs:** the owner keeps a machine switched on. An agent runs any command on it as the runner's user, and what one job leaves on it outside its home folder is there for the next (`decisions.md` [A426c](../decisions/426.md)), where GitHub's runner is new for each job. A runner takes one job at a time, so jobs wait for it, unbilled; GitHub cancels a job that waited 24 hours.
- **Counting it:** `minutes.sh` and `ticket-cost.sh` bill no minute to a job whose runner group is not `GitHub Actions`, the group GitHub gave the hosted runner of run 44653556115 (`decisions.md` [H426](../decisions/426.md)). No self-hosted runner had been registered when this was written, so the group GitHub gives one was not seen: the first day with the variable set is the test, and `minutes.sh` over that day shows the four jobs billed 0 beside the minutes they ran.
- **Automated:** partly. The workflows read the variable by themselves. Registering the runner needs the owner's machine and admin rights on the repo, which the factory does not hold (`decisions.md` [U2](../decisions/36.md)).
