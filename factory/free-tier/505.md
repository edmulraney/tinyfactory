### #505. A build cut short that waits with `ready` holds no place

- **Set:** `in-flight.sh full` no longer counts a ticket that waits with `ready` beside the draft pull request its build left unfinished, so `start-build.sh` and `start-waiting.sh` start five builds beside any number of such tickets (ticket #505; `decisions.md` [T505a](../decisions/505.md) to [T505d](../decisions/505.md)). This adds to the numbers of [entry #481](481.md).
- **Protects:** the owner's time and the factory's speed, at the price of Neon's preview slots.
- **What happened:** on 20 November 2026 the usage limit cut five builds short ([entry #395](395.md)). Each draft counted as a ticket being built, so when the hold was lifted `start-waiting.sh` started one build of the five, and a person started the other four by hand.
- **Numbers, database branches:** each open pull request that Vercel builds holds one of Neon's 9 preview slots ([entry 8](entry-8.md)). Before, a draft left unfinished was one of the five tickets being built or checked, so five of those and five pull requests waiting for the owner could ask for 10 slots ([entry #481](481.md)). Now each cut-short ticket that waits beyond the five being built adds one open draft to those 10: six builds cut short at once leave one waiting, and 11 open pull requests at most. A pull request with no slot fails its preview with "Branch limit reached", and a push after a slot frees builds it ([entry 8](entry-8.md)). The drafts were open before this change too; what is new is that five builds run beside them.
- **Numbers, Actions minutes:** worked out, not measured. No job is added: `in-flight.sh` makes one more call to GitHub only when a draft was left unfinished, and `start-waiting.sh` two more for each cut-short ticket it tells, in jobs that already run.
- **Automated:** yes.
