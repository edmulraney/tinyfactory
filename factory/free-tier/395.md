### #395. No agent starts while the Claude usage limit holds

- **Set:** a session the usage limit ends records the reset time on the `sessions` branch (`usage-limit.sh hold`), and until then a build, fix round, review, retro and Peta's run each end at their first step, keeping their place; `flag-idle.sh` starts them again at its first look after the reset, and `resume.yml` at once (ticket #395; `decisions.md` [A231b](../decisions/231.md), [A395a](../decisions/395.md) to [A395f](../decisions/395.md)).
- **Protects:** Actions minutes, the Claude subscription's usage limits and the owner's time.
- **Why:** the limit covers the whole account, so a session started before it resets ends at once with no work done, in a job that is billed all the same.
- **Numbers, before:** on 18 November 2026 five fix rounds ended at the limit with no work, and the owner started each again by hand. On pull request #390 one of them took the third place of three, so two later findings started no round and the pull request stopped for a person twice more.
- **Numbers, as set:** worked out, not measured: a workflow cannot run before it merges. A held run ends in under a minute, billed as one, where the session it refuses was billed the job's setup first: a fix round checks out twice and installs Playwright before its engineer starts. The check is one read from GitHub in a job that already runs. No schedule is added: the look that lifts the hold is `flag-idle.yml`'s ([entry #271](271.md)), so what was held starts up to six hours after the reset.
- **Automated:** yes.
