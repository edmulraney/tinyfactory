### #640. End-to-end tests run on four workers

- **Set:** the Playwright step of the `e2e` job in `ci.yml` runs `pnpm test:e2e --workers=4`, so four test files run at once where one did (ticket #640; `decisions.md` [M640b](../decisions/640.md)).
- **Protects:** Actions minutes, and the job's 25-minute limit.
- **Why:** Playwright gives itself one worker for each two cores, and the runner has two, so the suite ran one file at a time. Its tests mostly wait on the preview, not on the runner.
- **Numbers, before:** on 2026-11-22 the `e2e` job of run 45032214836 (pull request #778) ran 214 tests on one worker in 23.4 minutes, and the job took 24.5 minutes, of the 25 it is allowed. The next run of the same app code was cancelled at that limit (run 45033818325).
- **Numbers, after:** worked out, not measured. Dealing that run's 56 files (28 at each of two screen widths) to four workers in the order Playwright ran them takes 373 seconds where one worker took 1,392, so the job would take about 7.3 minutes and be billed 8 where it was billed 25. The suite can grow to about twice its size before the job reaches 15 minutes.
- **What it does not save:** a pull request that changes no app code already skips the tests ([entry #75](75.md)), and still bills its one minute.
- **Automated:** yes.
