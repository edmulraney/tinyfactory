### #631. Shipped initiatives are measured once a week

- **Set:** `measure-initiatives.yml` runs each Monday at 05:23 UTC as one job, skipped where no Neon project is set, whose script `measure-initiatives.sh` posts a comment on an initiative's ticket only when its verdict changes; the step that reads production's counts is [entry #635](635.md) (tickets #631 and #641; `decisions.md` [M631a](../decisions/631.md) to [M631f](../decisions/631.md), [M641a](../decisions/641.md)).
- **Protects:** Actions minutes.
- **Why:** a metric counts a whole week, so a look more often than weekly reads nothing new, and every look is billed a whole minute.
- **Numbers, as set:** worked out, not measured: a workflow cannot run before it merges. 1 billed minute each Monday, as `review-notes.yml`'s one-step job is billed ([entry #241](241.md)): about 4 of the month's 2,000 minutes, and none in a repository with no Neon project, where the job is skipped. A verdict is a comment, which no deployment builds.
- **Numbers, the alternatives:** daily, about 30 minutes a month, for the same one reading a week. A file of each verdict on `main`, as first built: a commit that Vercel builds ([entry #165](165.md)) each time a verdict changes, 1 of the day's 100 deployments.
- **The event-driven way:** none will do. A date that has come is time passing, which no event marks, and nothing happens in the repository when a user uses the product.
- **Automated:** yes.
