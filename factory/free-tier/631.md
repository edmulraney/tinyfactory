### #631. Shipped initiatives are measured once a week

- **Set:** `measure-initiatives.yml` runs each Monday at 05:23 UTC as one job, whose script `measure-initiatives.sh` pushes a file only when a verdict changes; the step that reads production's counts is [entry #635](635.md) (ticket #631; `decisions.md` [M631a](../decisions/631.md) to [M631f](../decisions/631.md)).
- **Protects:** Actions minutes, and Vercel's deployments.
- **Why:** a metric counts a whole week, so a look more often than weekly reads nothing new, and every look is billed a whole minute.
- **Numbers, as set:** worked out, not measured: a workflow cannot run before it merges. 1 billed minute each Monday, as `review-notes.yml`'s one-step job is billed ([entry #241](241.md)): about 4 of the month's 2,000 minutes. A week in which a verdict is written or changes adds one commit under `product/`, which Vercel builds ([entry #165](165.md)): 1 of the day's 100 deployments.
- **Numbers, the alternatives:** daily, about 30 minutes a month, for the same one reading a week. A file of every week's reading: a commit and a deployment each week for every measured initiative, where the verdict alone costs one each time it changes.
- **The event-driven way:** none will do. A date that has come is time passing, which no event marks, and nothing happens in the repository when a runner uses the product.
- **Automated:** yes.
