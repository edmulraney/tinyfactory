### #571. Dara and her browser run only for a proposal with a screen

- **Set:** in `refine.yml`, the `setup` action and Dara's session run only when Peta's proposal leaves `.refine/screens.md`, which she writes for a slice that adds or changes a screen (ticket #571; `decisions.md` [A571a](../decisions/571.md)). Dara's session has 60 turns and the job keeps its 30 minutes ([A571e](../decisions/571.md)). The runner's own Chrome draws the designs, so the run installs no browser ([D571a](../decisions/571.md)).
- **Protects:** Actions minutes in a private repo, and the Claude subscription's usage.
- **Why:** a designer who ran on every proposal would cost a session and an install of the packages for an idea that has no screen, and for each run in which Peta files tickets or stops.
- **Numbers, before:** the four `refine` runs that ran Peta on 21 November 2026 (44845185272, 44845535861, 44901296356, 44902212986) had jobs of 127, 167, 126 and 104 seconds, billed 3, 3, 3 and 2 minutes of the 2,000 a month. Her four sessions cost $1.08, $1.37, $0.94 and $0.59 at API prices, in 25, 22, 10 and 7 turns.
- **Numbers, after:** worked out, not measured: a workflow cannot run before it merges. A run with no screen is as before. A run with a screen adds the `setup` action with no browser, which took 17 seconds in the `checks` job of `ci` run 44909859101 on 21 November 2026, each picture, which took about 2 seconds on a runner, and Dara's session. Her session reads about what Peta's reads and writes more, so it is taken to cost no less than Peta's $0.59 to $1.37 and 68 to 127 seconds, and her 60 turns and the job's 30 minutes bound it. The retro of the changed workflow's first run measures it ([T185](../decisions/185.md)).
- **The event-driven way:** Peta's proposal is the event, in the run that already holds it, and nothing is scheduled.
- **Automated:** yes.
