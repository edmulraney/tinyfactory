### #596. A local `pnpm test` runs only the factory tests a change can affect

- **Set:** given no commit, as in `pnpm test`, `test-factory.sh` compares the working tree with the commit where the branch left `origin/main`, and runs only the test files that change can affect, as [entry #429](429.md) has `ci` do (ticket #596; `decisions.md` [H596a](../decisions/596.md), [H596b](../decisions/596.md)). A change to `pnpm-lock.yaml` no longer runs every file.
- **Protects:** Actions minutes, and the 60 minutes a build session may take.
- **Why:** an engineer runs `pnpm test` several times in a build, and each run took every test file whatever had changed.
- **Numbers, before:** the build of ticket #582 ran all 102 test files seven times, about 30 of its 60 minutes, and was killed 3 minutes into its last verification with no pull request ready for review.
- **Numbers, after:** worked out, not measured: for a change to one script the affected files take 143 seconds at the median against 352 for all 94 files, on the machine and at the time [entry #429](429.md) measured.
- **Not measured:** the time a build session spends in `pnpm test` after this change; the log of a later build shows it.
- **When the commit or the changed files cannot be read, or nothing has changed:** every test file runs, at the old cost.
- **Automated:** yes.
