### #269. A waiting ticket is started by the merge that frees its place

- **Set:** `start-build.sh` leaves `ready` on a ticket that finds no place free, and `start-waiting.sh` starts the tickets that wait, in the queue's order (`decisions.md` [T335a](../decisions/335.md)), while a place is free. `ship.sh` runs it after each merge; `start-waiting.yml` runs it when a person closes, unmerged, a pull request the factory opened (ticket #269; `decisions.md` [T64c](../decisions/64.md), [T64d](../decisions/64.md), [T269a](../decisions/269.md), [T269b](../decisions/269.md)). This replaces part of [entry 16](entry-16.md): a fourth ticket is no longer refused.
- **Protects:** the owner's time, at the price of Actions minutes.
- **Why:** a refused ticket had to be labelled again by hand once a place was free, and nothing said when that was.
- **Numbers, before:** on 17 November 2026 a session added `ready` again about twenty times in a morning. Each refusal was a run of `implement.yml` billed as 1 minute, and each was repeated until a place was free.
- **Numbers, after:** worked out, not measured. A ticket that waits costs 2 billed minutes more than one that finds a place: the run that makes it wait, and the build's own run started later. After a merge with nothing waiting, `ship.sh` makes one more call to GitHub in a job that already runs; with tickets waiting, two more, one for each ticket that waits, and one for each build started.
- **Numbers, the new workflow:** 1 billed minute each time a person closes, unmerged, a pull request the factory opened. The factory's own merges start no workflow, and a person's pull request or a merged one is skipped by a condition on the job, which is billed nothing; a merge with GitHub's merge button is billed the job that follows any merge (`decisions.md` [M435a](../decisions/435.md)).
- **Numbers, tickets labelled at the same moment:** one more call to GitHub, and only in a run that finds no place was free after taking its own. Rejected again, a job holding one concurrency group: a billed minute on every ticket (`decisions.md` [T64d](../decisions/64.md)).
- **Automated:** yes.
