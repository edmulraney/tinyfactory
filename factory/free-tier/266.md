### #266. No review of a build's empty first commit

- **Set:** the `e2e` job in `ci.yml` runs `needs-review.sh`, and the `adam` and `ryan` jobs carry a condition on its answer: neither starts for a commit that is the only one on its branch and changes no file (ticket #266; `decisions.md` A266a, A266b). The three skills that build mark a pull request ready only after their last push (A266c).
- **Protects:** Claude usage and Actions minutes.
- **Why:** a pull request marked ready before its work is pushed holds only the commit its draft was opened on, and both reviewers read it, passed it and had the owner asked for an approval.
- **Numbers, before:** it happened on pull requests #228 and #265. On #265 the pull request was marked ready at 13:14 and its change was pushed at 13:19 on 17 November 2026: two verdicts on commit 2dc3c98, then two more on the change. A pair of reviews is about 5.3 billed minutes and $2.50 (entry #160).
- **Numbers, after:** worked out, not measured. Two skipped jobs are billed nothing, so such a run saves the pair: about 5 minutes and $2.50. The step is one call to GitHub in a job that already runs, and adds no billed minute to any other run.
- **What it does not skip:** `checks` and `e2e` run for that commit as before; the push that follows starts a run that does everything.
- **When GitHub cannot be read:** both reviews run, at the old cost (`decisions.md` A266b).
- **Automated:** yes.
