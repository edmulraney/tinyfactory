### #361. Pull requests that wait for the owner are counted apart, five at most

- **Set:** `in-flight.sh full` lets a build start while fewer than three other tickets are being built or checked and fewer than five pull requests wait for the owner; `start-build.sh` and `start-waiting.sh` ask it (ticket #361; `decisions.md` T64a, T361a to T361c). This replaces part of entry 16: a pull request that waits for the owner no longer takes one of the three places.
- **Protects:** the owner's time and the factory's speed, at the price of Neon's preview slots.
- **What happened:** on the night of 17 November 2026 two pull requests that waited for the owner held two of the three places for nine hours, so one ticket was built at a time.
- **Numbers, database branches:** each open pull request holds one of the 9 preview slots (entry 8). Before, three in flight held 3 and left 6. Now three being checked and five waiting hold 8 and leave 1, for a pull request merged since checks last ran, a person's own pull request, or a branch a cut-short build left (entry 13). When those need more than 1, the next preview fails with "Branch limit reached", and pushing again once checks have run builds it (entry 8).
- **Numbers, Actions minutes:** worked out, not measured. No job is added: the merge gate, in a job that already runs, makes four to six more calls to GitHub when it holds a pull request. Each pull request that waits is tested with `main` again when it merges after `main` moved: 2 to 3 minutes (entry 10), as before.
- **Automated:** yes.
