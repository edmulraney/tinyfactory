### #672. A preview's database branch is deleted once its end-to-end tests pass

- **Set:** the `delete-preview` job of `ci.yml` runs once `e2e` has run the tests and passed, and deletes the pull request's `preview/…` Neon branch unless a newer commit has been pushed since; the next build of the app makes the branch again from production's (`decisions.md` [M672a](../decisions/672.md)). A later commit with no app file changed since the commit whose tests passed skips its tests, as `ci.yml`'s comment on that pass lets `needs-e2e.sh` tell ([M672c](../decisions/672.md)). Every six hours `flag-idle.yml` deletes each `preview/…` branch whose git branch no open pull request is built from, in place of the sweep that ran in `checks` ([M672b](../decisions/672.md); [entry 8](entry-8.md)).
- **Protects:** Neon's storage, and Neon's 9 preview slots.
- **What happened:** on 22 November 2026 Neon reported the project at 100% of its storage and warned that production might fail to connect. Production held about 42 MB, and the preview branches had written 1.29 GB since each was made from production. Each test writes a runner, races and a Garmin history; every push ran the suite again on the same branch, which lived as long as its pull request.
- **Numbers, storage:** before, a branch grew with every push for its pull request's whole life. After, a branch holds one push's tests at most, and none once they have run. Not measured yet.
- **Numbers, branches:** before, a pull request held a slot from its first build until its git branch was deleted, and a closed pull request's live git branch held one for good. After, it holds one from a build of the app until that build's end-to-end tests pass, and a closed pull request's at most six hours. A draft still holds one from its first build until it is marked ready ([M660d](../decisions/660.md)).
- **Numbers, Actions minutes:** the job is billed one minute for each run of `ci.yml` whose end-to-end tests passed; a run whose tests failed or were skipped skips it. A run on a commit with the app of one whose tests passed now ends its `e2e` job at the question, about a minute where Playwright took several. The step in `flag-idle.yml` adds seconds to a job that already runs, so no minutes.
- **The event-driven way:** the deletion after the tests is one. Deleting a closed pull request's branch on its `closed` event would not do: Vercel can make the branch after the close, and nothing tries a failed delete again.
- **Automated:** yes, with the `NEON_API_KEY` secret and the `NEON_PROJECT_ID` variable that setup stores ([entry 8](entry-8.md)). A project without the variable skips both steps.
