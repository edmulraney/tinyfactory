### #429. Only the factory tests a change can affect run

- **Set:** in the `checks` job of `ci.yml` and in a group's test, `test-factory.sh` is given the commit of `main` and runs only the test files that name a changed file, directly or through the shell files that name it (ticket #429; `decisions.md` [H429a](../decisions/429.md) to [H429e](../decisions/429.md)). A change to `test-factory.sh`, to `helpers.sh`, to a workflow, under `.github/` or to the root's three package files runs every file, and so does `pnpm test`.
- **Protects:** Actions minutes.
- **Why:** the factory's tests are most of the `checks` job, which billed 3.3 minutes a job from 14 to 18 November 2026 ([entry #388](388.md)), and a change to one script ran every file.
- **Numbers, before:** on the two-processor machine that built ticket #429, the 94 test files took 352 seconds together. `ship.test.sh` alone took 132.
- **Numbers, after:** worked out on that machine from each file's own time, for a change to each of the 85 scripts in `factory/scripts/` alone, taking the files two at a time. Such a change runs 15 of the 94 files on average. It takes 143 seconds at the median and 111 on average, against 352; for 37 of the 85 scripts it takes under 60 seconds, and for one script, `test-factory.sh`, all 352. A change to `ship.sh` runs 21 files in 166 seconds, and one to `shipping.sh` 33 files in 219. A change to documents and decision rows alone runs no test file.
- **Not measured:** the minutes a `checks` job is billed. A workflow cannot run before it merges; `factory/scripts/minutes.sh` prints them for the days after the merge, to set against the 3.3 before.
- **When the changed files cannot be read:** every test file runs, at the old cost (`decisions.md` [H429d](../decisions/429.md)).
- **Automated:** yes.
