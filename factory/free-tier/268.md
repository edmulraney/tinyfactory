### #268. Only the checks a change can affect run

- **Set:** in `ci.yml` the `checks` and `fits-main` jobs ask `checks-needed.sh` which files the change touches, and each check but lint carries a condition on its answer: typecheck, the app's tests and its build run for a change to `apps/`, `packages/`, `.github/actions/` or the root's three package files; the factory's tests run for a change to `factory/`, `.claude/`, `.github/` or those three files (ticket #268; `decisions.md` H268a to H268d). The checkout of `checks` is two commits deep, so that git can compare the merge with `main`.
- **Protects:** the owner's time, and Actions minutes.
- **Why:** since the reviews run beside it (entry #250), `checks` is the whole wait of a run, and it ran everything for every change.
- **Numbers, before:** the `checks` job took 3.8 minutes of a run's 4 (ticket #268). On the two-processor runner that built this ticket its five commands took 175 seconds: `pnpm lint` 14, `pnpm typecheck` 4, the factory's tests 145, the app's tests 1 and `pnpm build` 11. The rest is the checkout, the install and the smaller steps.
- **Numbers, after:** worked out from those figures, not measured: a workflow cannot run before it merges, and this ticket's token could not read the runs.
  - A change to the factory alone: 16 seconds less, so about 3.5 minutes, and the same 4 billed. Its own tests are what takes the time, and they still run.
  - A change to the app alone: 145 seconds less, so about 1.4 minutes, and 2 billed where there were 4.
  - A change to documents alone (`product/`, a rule document): 161 seconds less, so about 1.1 minutes, and 2 billed.
  - A change to both, to a shared action or to one of the root's three package files: as before.
  - `fits-main`, when it runs, saves the same.
- **When the changed files cannot be read:** every check runs, at the old cost (`decisions.md` H268c).
- **Automated:** yes.
