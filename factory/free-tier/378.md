### #378. A private repository stays on a personal account

- **Set:** nothing new. `github.sh` already creates the private repo under the logged-in user ([entry 6](entry-6.md)), and no setup script changed. This entry adds the source for [entry 6](entry-6.md) and the alternatives weighed (ticket #378; `decisions.md` [S378](../decisions/378.md)).
- **Protects:** the Vercel bill.
- **What happened:** on 18 November 2026 moving the repository into a GitHub organisation was weighed, so that an app's token could read the board's order, which `start-waiting.sh` reads with `BOARD_TOKEN` (`decisions.md` [T335a](../decisions/335.md)).
- **Source:** Vercel's documentation, read on 18 November 2026: "You cannot deploy to a Hobby team from a private repository in a GitHub organization, GitLab group, or Bitbucket workspace. Consider making the repository public or upgrading to Pro." (https://vercel.com/docs/git#using-hobby-teams)
- **Numbers:** on a personal account, a private repository deploys on Hobby for nothing. In an organisation, it deploys only on Vercel Pro, a paid plan ([entry 6](entry-6.md) has the price); a public repository there still deploys on Hobby for nothing.
  - Rejected, a private organisation repository on Vercel Pro: it costs money before the idea is proven.
  - Rejected, a public organisation repository: setup makes the repo private (`decisions.md` [S3](../decisions/setup.md)), and making it public is the owner's choice, not a way to move it.
- **Automated:** yes, by `github.sh`, as [entry 6](entry-6.md) says.
