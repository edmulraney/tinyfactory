| H3 | Each factory script has tests in `factory/tests/`, in a file named after it, and `test-factory.sh` runs them all inside `pnpm test`. | A test costs nothing per run where reviewers reading scripts found bugs at a fix round each, and `pnpm test` is where a person looks for tests. | Proof by description in the pull request. | H4 | The tests are plain bash with one shared helper, `factory/tests/helpers.sh`. | A new project has no new dependency to install, and the scripts are bash, so their tests read like their use. | bats or another test framework: one more dependency for every new project. | #56 |
| H5 | A test file that stops early, or runs no test, fails the check. | A file that broke half-way would otherwise read as a file whose tests all passed. | Trusting the exit code of the last test: a broken file reads as a passing one. | #56 |
| H6 | The scripts that hold a credential or decide something have tests, and every other script gets them when it next changes. | A bug in those costs the most (a wrong merge, a credential in the wrong hands), and other tests would be work with no ticket. | Tests for every script at once: work on scripts nobody is changing, with no ticket behind it. | #56 |
| H16 | A test runs the real script, with stand-ins for the outside commands it calls (`gh`, `curl`, `npx`) at the front of `PATH`. | The script under test, and the scripts it calls beside it, are the real files, so what is tested is what runs. | Rewriting the scripts so they can be unit-tested in another language: what is tested would not be what runs. | #56 |
| H17 | A stand-in answers with JSON through the caller's own `--jq` filter. | Running the caller's filter with the real `jq` means a wrong filter fails a test. | Stand-ins that print the final answer: every `--jq` filter would go untested. | #56 |
| H18 | Every test scenario starts with stand-ins that refuse every call. | No test then reaches the network, or passes because the real `gh` happened to answer. | Falling through to the real commands: a test would depend on the network and a login. | #56 |
| H19 | The code reviewer, not a script, fails a factory test that passes when its script is wrong, and asks for no test that is missing. | Only a reader can tell whether a test would fail for a wrong script. | A lint rule that fails any script without a test file: it would force tests for every script at once. Ryan asking for missing tests: a fix round each ([A256b](256.md)). | #56, #256 |
| H21 | `test-factory.sh` runs every test file even after one has failed. | One push then shows everything that is broken. | Stopping at the first failing file: one push for each failure. | #56 |
