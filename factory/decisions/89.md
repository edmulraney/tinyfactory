| A89b | Every caller starts a fix round through `start-fix-round.sh`: the `start-fix` job of `ci.yml`, and `ship.sh` for a pull request left in conflict. | One tested script checks the three-round limit before a round starts, and a new caller, such as the owner's review (#48), starts a round the same way. | Each caller starting `fix.yml` itself: the three-round stop copied into each. `fix.yml` watching `ci` end: [A20](70.md)'s billed minute on every failed run, and no start for a conflict. | #89 |
| A89c | A fix round is counted by a comment `record-fix-round.sh` posts after the engineer's step, and only when that step left an execution file. | Pull request #86 was stopped at three fix rounds without one engineer session, because the announcement posted before the engineer was the count. | Counting the announcement: a round that never ran is counted. Counting pushes: a round may rebut every finding and push nothing ([A69g](69.md)). | #89 |
| A89d | A fix round whose engineer step left no execution file fails its job, is not counted, and puts `needs-human` and why on the pull request. | The Claude action can skip itself and exit 0, and a green job that fixed nothing told nobody on #86 and #87. | Trusting the step's exit code: a skipped action exits 0. Starting the round again by itself: what stopped the session is likely still there. | #89 |
| A89e | `fix.yml` starts no engineer when the latest `ci` run for the pull request's head has no failed job and GitHub reports no conflict. | Two callers can ask for one pull request, and the second round would pay an engineer to fix what the first already pushed. | `ship.sh` leaving a pull request whose `ci` run is still going: a guard in one caller. Cancelling the queued run: runs cannot be found by their input. | #89 |
| A89f | `begin-fix-round.sh` lets a fix round run only for an open pull request the factory opened. | Anything that may start a workflow can start `fix.yml` with any number, and the engineer pushes to the branch ([M5](setup.md), [M13](21.md)). | Trusting the caller, as the job's condition in `ci.yml` did: a run started by hand can name anyone's pull request. | #89 |
| A89g | `fix.yml` finds what failed itself: the failed jobs of the latest `ci` run for the pull request's head, and a conflict GitHub reports. | Started with a number alone, it needs no `ci` run, which a pull request pushed in conflict never gets (#71). | The caller passing its run's id: `ship.sh` has none for a conflict, and a second input for every caller to get right. | #71, #89 |
